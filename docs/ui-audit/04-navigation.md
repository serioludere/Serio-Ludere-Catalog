## Dimension D — Navigation and Information Architecture

24 findings: **1 P0, 11 P1, 12 P2**. By realm: **admin 12** (incl. the P0), **public 8**, **customer 2**, **shared-sheet 6** (counted once, in whichever realm the selector actually renders — blast radius stated on each).

**Correction to the brief, verified:** the admin does **not** have "11 routes in a horizontal tab bar". The horizontal tab strip is _dead CSS_ (`admin.css:57-86`, `:660` — nothing in `src/` carries `class="tabs"`, see D-11). The live admin nav is a **220px left rail** in `src/components/ui/AppShell.astro:45-82`, styled in the **shared** `components.css:1186-1364`, carrying **5 destinations, not 11**, and it becomes a **3-cell fixed bottom tab bar** at `components.css:1319`. `admin.css:696` is the Customers-table card reflow, not the nav.

**The single worst problem (D-01, P0):** below 767px, `components.css:1338` hides `.shell__brand` — the only link to `/admin` — and `components.css:1361` hides `.shell__link--secondary`, the only links to `/admin/audit` and `/admin/google`. **Three of five admin destinations become URL-only on a phone**, with no hamburger, no overflow, no "More". `AppShell.astro:12` explicitly says dropping these from the nav "would strand them"; the mobile query strands them. `AdminLayout.astro:27-30` justifies lighting no rail item on `/admin` because it is "reached from the wordmark" — and below 767px the wordmark does not exist.

**Runner-up (D-06, P1):** the project's only background-scroll lock, `html:has(dialog[open]) { overflow: hidden }`, lives in `editorial.css:535` — a sheet loaded **only by the public catalogue**, which has one lightbox. All five admin overlays (Drawer, Modal, FetchModal, `#pwDialog`, `#confirm`) open over a freely scrolling page.

**Answers to the nine required checks are in the tables below** — including the 44px rule's exact coverage (it reaches three selectors and misses everything else), the overlay behaviour matrix, measured target sizes, the admin IA tree, and the answer to #9: **no navigation in this project is JS-driven, and none needs to be** — except that the public catalogue's nav is JS-_only_, which is the opposite problem (D-13).

## 10. Check #9 — does the mobile nav need JS?

**No, and none uses it.** Verified: the admin bottom tab bar is plain `<a>` elements reflowed by one media query (`components.css:1324-1336`) — no toggle, no drawer, no `client:*`, no hamburger, nothing to hydrate. The customer realm has no nav. The public realm's nav is CSS-only for _navigation_.

The exception runs the other way: the public collection nav is **JS-only** (**D-13**). `CollectionNav.astro:23` renders `<button type="button">` with no `href`, no form, and `index.astro` never reads `searchParams` (`const active = tabs[0]?.slug` at `index.astro:30` is unconditional). Without JS the primary navigation of the site is inert.

**If a `<details>`/`<summary>` disclosure is ever considered for an admin "More" menu (the natural D-01 fix), it is unnecessary** — the 3-cell bar plus one link to `/admin` reaches everything with zero JS and zero new markup patterns. Recommend that over a disclosure. No fix proposed anywhere in this dimension adds hydration, a `client:*` directive, an inline `<script>`, a `style="…"` attribute, `define:vars`, a dependency, or a `<ClientRouter/>`.
