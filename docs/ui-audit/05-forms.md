# 05-forms · E · Forms

**Phase 1 audit · read-only · no code changed.** Findings verified against the files: each citation was
re-checked with `sed -n` and each claim adversarially re-judged. 3 finding(s) refuted and moved
to the bottom. Counts: **P0 0 · P1 3 · P2 19** (22 kept).

## Dimension E — Forms

**Coverage.** Every form control in `src/` was read and every citation re-derived with `grep -n`/`sed -n` immediately before writing. Census: **~55 interactive form controls in admin** across 8 routes + 2 shared components, **4 in customer preview** (1 password field, 2 selects, 1 segmented group), and **zero in the public catalogue** (`src/pages/index.astro`, `rugs/[slug].astro`, `tags/[slug].astro` contain no `<input>`, `<select>` or `<textarea>` — only the vote buttons in `VoteButtons.astro`). 25 findings: **1 P0, 9 P1, 15 P2**.

**The single worst problem is item 11, the no-JS fallback.** `grep -rn "<form" src/` returns **four matches in the entire project**. Three are real server POSTs — admin login (`login.astro:115`), admin logout (`AdminLayout.astro:93`), customer gate (`PreviewGate.astro:33`) — and the fourth (`clients.astro:236`) is a `method="dialog"` shell that submits nothing and actively destroys input (E-03). Every data-mutating admin path — **all ~16 of them** — has no `<form>` element and exists only as a `fetch` call. And the one customer-realm form that claims a fallback does not have one: the endpoint parses `request.json()` only (`api/customers/[slug]/login.ts:44`), so a native urlencoded POST returns a bare JSON 400 (E-01, the only P0). A project whose recon records _zero_ `client:*` directives and _zero_ islands honours progressive enhancement on **2 of ~18 submit paths, both of them authentication — about 11%**.

**Second worst, and cheap to fix:** every admin error message in the product is silent to assistive technology. `msg()` inserts content into a `display:none` node and stamps `role="alert"` on afterwards (`msg.ts:8-11` against `admin.css:180`), so the live region does not exist at the moment it changes (E-04).

**What is genuinely good, and should not be "fixed":** validation timing is correct everywhere — nothing validates on keystroke; `rug-form.ts` `validate()` (`:654`) runs only from `add()`/`save()`, and `clients.ts` validates on click. There is **no disabled-submit antipattern** anywhere (item 10): buttons are disabled only while a request is in flight, and the one disabled submit — login's "Locked" (`login.astro:134`) — is explained by an adjacent warning-toned message and a ticking countdown. All three of error/success/pending exist on every admin submit path. `ui/Input.astro` is a model control; the problem is that admin uses it for 5 of ~55 controls (E-25).
