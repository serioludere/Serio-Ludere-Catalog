## Dimension F — Accessibility (WCAG 2.2 AA) and Performance

**Coverage.** All three modes resolved from `src/styles/modes.css` and cross-checked against the 63-token × 3-mode `EXPECTED` fixture in `tests/unit/styles/token-cascade.test.ts`; 135 contrast ratios computed with a WCAG-relative-luminance script (working shown below). All 11 admin routes, 3 public routes and 2 customer routes read for heading order and landmarks. All 14 `<img>` audited attribute-by-attribute. All 10 `prefers-reduced-motion` blocks enumerated and tested for escapees. All 190 class names in `components.css` cross-referenced against every `.astro`/`.ts`/`.js` file in `src/`. CSS bytes measured per realm.

**Counts.** 38 findings — 3 P0, 16 P1, 19 P2. By realm: admin 19, shared 11, public 5, customer 3. Five are FLAG-ONLY or fidelity-locked with no change proposed (F-16, F-18, F-20, F-21, F-25, F-34, F-35).

**Confirmations.** Recon D1 (preview loads Inter only while `var(--mono)` renders) verified at three sites. Recon D5 undercounts: there are **ten** reduced-motion blocks, not nine. GSAP confirmed dynamic-only (`src/scripts/tabs.ts:45`). `modes.css:408`'s claimed 3.18:1 for admin-dark success/danger verified exactly. Zero `client:*` directives, zero `outline: none`, zero `prefers-contrast`/`forced-colors` rules.

**The single worst problem: `[data-mode='admin-dark']` is a larger contrast failure than its own comment admits, and the owner has decided to ship it.** `modes.css:405-409` warns about two pairs at 3.18:1. There are at least **nine** failing pairs, and the three worst are undocumented: black text on the inherited brand-red primary hover is **3.10:1** (F-01), on the `:active` red **2.46:1** (F-02) — below even the 3:1 non-text floor — and on `--surface-raised` (#403f3c, the ground for every modal and drawer) success is **1.96:1** and danger **1.97:1** (F-05). Separately, `--rule`, `--subtle` and `--surface-raised` all resolve to the same primitive there, so every hairline inside a modal or on a hovered row renders at **1.00:1** (F-04). The mode cannot ship on the strength of fixing the two pairs the comment names.

**Runner-up (light modes, already shipping):** `--ink-muted` was derived against three grounds but not against `--subtle`, which is the darkest one it is read on — **4.196:1**, failing AA at 11px on the admin nav's hover state and on every revoked/striped customer row (F-07).

**Performance headline:** `/admin/rugs` serialises every product **twice** with no pagination on an uncached route (F-32), and the customer detail page paints 96px thumbnails from **1600px** sources while the proxy's `?w=400` tier is generated nowhere in the codebase (F-31).

## Method — worked example

Computed with WCAG 2.x relative luminance: linearise each sRGB channel (`c ≤ 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`), `L = 0.2126R + 0.7152G + 0.0722B`, ratio `= (L_light + 0.05) / (L_dark + 0.05)`.

**Worked pair — `--ink-muted` on `--subtle` (finding F-07):**

| step | `#73726c` (`--ink-muted`, modes.css:205) | `#efefef` (`--subtle`, modes.css:200) |
|---|---|---|
| RGB | 115, 114, 108 | 239, 239, 239 |
| sRGB /255 | 0.45098, 0.44706, 0.42353 | 0.93725, 0.93725, 0.93725 |
| linearised | 0.171441, 0.168269, 0.149960 | 0.863157, 0.863157, 0.863157 |
| L | **0.167622** | **0.863157** |

`(0.863157 + 0.05) / (0.167622 + 0.05) = ` **4.1961 : 1** → required 4.5 (11px text, not large) → **FAIL**.

**Verification against source, not fixture:** `modes.css:55` declares `--color-neutral-550: #73726c`; `modes.css:205` aliases `--ink-muted` to it; `modes.css:23` declares `--color-neutral-200: #efefef`; `modes.css:200` aliases `--subtle` to it. The `token-cascade.test.ts` `EXPECTED` rows agree (`'--ink-muted': ['#73726c','#73726c','#8c8b84']`, `'--subtle': ['#efefef','#efefef','#403f3c']`). Fixture and sheet are consistent; all ratios below are computed from the sheet.

## Hydration audit (item 14) — no islands, 32 modules

Confirmed zero `client:*` directives and zero framework islands. Client behaviour is 32 modules loaded by Astro-bundled `<script>` tags, hoisted per page. Per-route module counts: `/admin/rugs` loads 5 (`rug-list`, `view-switch`, `inline-row`, `ui/overlay`, `rug-form`) plus `ui/reveal` via `Input.astro:138` — the heaviest. `/admin/clients` loads 3 + reveal. `/` loads `tabs`, `lede`, `prefs`, `photos`, `votes`, `transitions`. `/[slug]/[productId]` loads `preview-gallery`, `prefs`, `customer/sort`, `votes`, `prepaint`.

**GSAP confirmed out of the initial bundle:** `src/scripts/tabs.ts:45` — `Promise.all([import('gsap'), import('gsap/Flip')])`, a true dynamic import, gated at `tabs.ts:40` behind a reduced-motion check. It is not in any entry chunk.

**The deferrable one:** `src/components/ui/Input.astro:138` pulls `ui/reveal.ts` into the bundle of every page that renders *any* `Input`, including pages with no `type="password"` field at all (`/admin/rugs` renders a select-type Input in the filter bar). `bindReveal` no-ops correctly, so this is bytes, not behaviour. Move the script out of `Input.astro` and import it from the two pages that actually have password fields (`login.astro`, `clients.astro`), or gate the component-level script on `type === 'password'`.

No module should be *added*; no fix in this report adds hydration, a dependency, an inline `<script>`, a `style=` attribute, or a `define:vars`.
